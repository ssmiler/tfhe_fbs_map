# Heuristic for mapping Boolean circuit to TFHE functional bootstrapping

This repository contains the code used in paper *[A fast heuristic for mapping Boolean circuits to functional bootstrapping](https://eprint.iacr.org/2024/1204)*.

## Mapper

The mapper is implemented in dependency-free Rust. It accepts two-input BLIF circuits, ISCAS-style BENCH files, and Bristol Fashion circuits, verifies generated mappings by default, and writes the human-readable FBS and LBF formats. BENCH format `AND`, `OR`, `NAND`, `NOR`, `XOR`, and `XNOR` gates are lowered to two-input chains; `NOT` and `BUFF` are also supported. The CLI detects `.bench` files automatically; use `--type bristol` for Bristol files.

Build and run it with:

```bash
cargo build --release
target/release/fbs-map circuit.blif \
    --fbs-size 3 \
    --mapper search \
    --trials 3 \
    --output circuit.fbs \
    --output-lbf circuit.lbf
```

The available mapping policies are:

- `basic`: maps every Boolean gate separately.
- `naive`: composes adjacent cones with fixed-coefficient rule (`x1 + 2.x2 + 4.x3 + ...`).
- `search`: composes adjacent cones by searching coefficient pairs which minimize resulting FBS size (paper heuristic).

`--trials N` runs the selected mapper first with the topological order encoded in
the circuit, then with `N - 1` deterministic random topological orders derived
from `--seed`. The best mapping is retained and total mapping time is reported.

Use `--max-norm2 N` to enforce the squared Euclidean-norm constraint of every unbootstrapped cone. By default, the negacyclic extension permits test vectors up to `2p`; `--strict-fbs-size` limits them to `p`. Run `target/release/fbs-map --help` for all controls.

With `--multioutput-fbs`, bootstrap outputs that use the same input linear
combination are emitted as one multi-output FBS and counted once. Without the
flag, every Boolean bootstrap output remains a separate FBS. For example, the two
full-adder outputs share the input `a + b + cin` and can be represented as one
bootstrap with two test vectors.

The flag also changes mapping decisions: an encoding compatible with an existing
bootstrap input has zero marginal FBS cost, and a cone is realigned to a
compatible existing encoding before it is bootstrapped. Shared cones and circuit
outputs are kept unbootstrapped while mapping, so when a downstream merge only
scales a predecessor's linear form, that predecessor's other outputs and the new
cone are emitted by the same multi-output FBS.

The full-adder regression fixture gives the following results at `p=3`:

| mapper | bootstraps | maximum LUT | maximum norm² |
| --- | ---: | ---: | ---: |
| `basic` | 5 | 4 | 5 |
| `search` | 4 | 5 | 6 |

All mapper unit tests, including exhaustive equivalence checks and deterministic random DAGs, run with:

```bash
cargo test --release
cargo clippy --all-targets --all-features -- -D warnings
```

## How to run the experiments

### Preliminaries

Install the Python packages used by benchmark generation and result analysis,
then go to the `experiments` directory:
```bash
pip3 install -r requirements.txt
cd experiments
```

Clone `concrete` library and patch it to support non power-of-two parameters:
```bash
git clone https://github.com/zama-ai/concrete.git -b nightly-2024.04.17
(cd concrete; git apply ../concrete.patch)
cargo build --release --manifest-path concrete/compilers/concrete-optimizer/Cargo.toml --bin v0-parameters
```

`add_exec_estimates.py` calls the compiled `v0-parameters` binary directly.

### Run the benchmarks

The sequential ISCAS89 circuits are unrolled into ten frames by
`unroll_bench.py`, with one additional input per flip-flop for its initial state
(`latch_name__f0`). Each later frame receives the previous frame's next-state
value. No external logic-synthesis tool is required. The generated combinational
BENCH files are then read directly by the Rust mapper.

```bash
python3 unroll_bench.py input.bench output.bench --frames 10
```

Use the following script to execute all the benchmarks (it should take less than 20 minutes):

```bash
bash run_benchmarks.sh
```

The script creates a `Makefile` for each benchmark suite (`epfl`, `iscas85`, etc.).
The targets in the makefile are the calls of the mapping heuristic with specific parameters.
The output of each makefile execution is streamed to a log file (`outputs/epfl.log` for EPFL benchmarks, etc.).
Use `tail -f outputs/epfl.log` to follow benchmark executions.


As example, in the EPFL benchmarking makefile (generated by `gen_makefile_epfl.bash`) the target (`outputs/epfl/adder_15_search.fbs`) will execute the `search` flavor of the Rust mapping heuristic on circuit `benchmarks/epfl/arithmetic/adder.blif` with functional bootstrapping size `15`.
The respective makefile lines:

```
...
outputs/epfl/adder_15_search.fbs outputs/epfl/adder_15_search.lbf outputs/epfl/adder_15_search.log: benchmarks/epfl/arithmetic/adder.blif | outputs/epfl
        ../target/release/fbs-map benchmarks/epfl/arithmetic/adder.blif --fbs-size 15 --mapper search --output outputs/epfl/adder_15_search.fbs --output-lbf outputs/epfl/adder_15_search.lbf > outputs/epfl/adder_15_search.log 2>&1
...
```


### Analyse results

The following script will interpret the mapping results obtained after the benchmarks execution and generate tables (latex code) and figures used in the paper.

```bash
cd outputs
python3 ../analyse_results.py
```

> [!NOTE]
> The script `analyse_results.py` only outputs raw latex code (e.g. only latex table content is generated without table floats instructions)
